# Hosting, integrations, and caches

## Capture the provider inventory

- Match the exact manifest Pages project, account, production hostname, custom aliases, deployments and preview aliases. Check DNS records and rule targets, OIDC client and redirects, lifecycle hooks, GitHub environments and pending deployments, and any relevant mobile store, webhook, or automation provider. Use authenticated read-only access where available and keep sensitive inventory private. A local manifest or public DNS result proves only its own layer.
- Disable the retired app's publish and recreation paths. Check running and scheduled jobs, deployment hooks, provider Git integration, and pinned automation or old refs. Keep shared deployment paths usable for surviving applications. For authorized rollback windows, record the exact artifacts and architectures that can still serve compatible data.

## Retire Pages and its integrations

1. Stop serving or repopulating the retired content. If there is a transition window, coordinate the replacement or retirement response with the frontend and runtime rollout. Perform any cleanup that needs an active browser origin before detaching it. Verify the old content is unavailable from the attached origin after the scoped cache purge. For a custom domain, perform the purge and response checks while it can still be reached when feasible. [Serving Pages](https://developers.cloudflare.com/pages/configuration/serving-pages/#caching-and-performance)
2. Detach only the app-owned custom hostname and exact DNS record, or reconcile them with an explicitly approved successor. Confirm the record ID, type and destination and the domain association before changing either. Check app-specific cache, redirect, Access and tunnel rules for stale references. Use the authorized operator path for DNS managed by the runtime's `dns.apply` plans. [Remove a Pages custom domain](https://developers.cloudflare.com/pages/configuration/custom-domains/#delete-a-custom-domain)
3. The repository's shared `scripts/pages.ts` implements plan, provision, deploy, and verify. Use the authorized Cloudflare dashboard or Pages API for deletion of the exact project after any rollback window. Re-read project and deploy inventories in the verified account and test saved production, branch, and deployment URLs for absence of the old artifact. For a project that will remain, enumerate and reconcile the exact deployments and project build cache that are in scope. [Pages project and build cache API](https://developers.cloudflare.com/api/resources/pages/subresources/projects/)
4. Remove the exact `<origin>/auth/callback` URI, any registered native callback URI, approved web origins, and any target-only logout URI from the existing OIDC configuration. Retire a client or revoke its sessions only at its verified ownership boundary. Protect shared audiences and issuer/client configuration. Disable app-owned webhooks, payment entry points, scheduled triggers, and deploy hooks at their planned cutoff. For payments, close entry points first and finish or transfer outstanding settlements and provider retries before retiring callbacks, reconciliation jobs, or credentials. Restrict native distribution and OTA channels if an approved store release is in scope and record the status of already installed builds.

## Evict app-owned cache and generated state

| Layer                     | Scope and evidence                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cloudflare edge           | For the managed custom zone, purge exact URLs or an exclusive hostname, prefix, or tag. Include custom cache-key variants where used. Check representative old URLs and `CF-Cache-Status` where observable. Use verified Pages project and deployment removal plus direct probes for provider-owned `pages.dev` URLs. Use scoped purge methods in a shared zone. [Cloudflare purge methods](https://developers.cloudflare.com/cache/how-to/purge-cache/) |
| Runtime or storage cache  | Inspect actual deployments for app-specific process caches, key-value entries, reverse proxy caches, and cached object URLs. Delete exact keys or proven exclusive prefixes and confirm no writer recreates them. Keep shared cache stores and other tenants' keys.                                                                                                                                                                                      |
| Local and CI artifacts    | Reconcile the app's `dist/`, frontend `.state/pages/<slug>.json`, scaffold manifests, generated files, and app-owned Vite, Expo, CI or preview caches that actually exist. Verify paths and ownership before removing ignored artifacts. Retain approved release or audit evidence and shared package stores.                                                                                                                                            |
| Browser and native device | For reachable clients, retire any app-owned service worker and caches, storage, and sessions from the correct origin or app sandbox. On a shared origin use verified feature-specific keys. Verify in a fresh session and with an existing cached or offline client where applicable. Use server-side denial and provider revocations for old clients. Record unreachable devices and browser copies separately.                                         |

Check authoritative DNS and a fresh external client after removal, allowing for DNS caching. Inspect the old response body or artifact marker as well as status, since generic error pages, redirects, and cached content can all respond. Confirm integrations are absent or disabled from authenticated provider inventory and test surviving Pages and OIDC flows independently.
